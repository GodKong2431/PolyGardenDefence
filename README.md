# PolyGardenDefence

PolyGardenDefence는 로우폴리 스타일의 3D 타워 디펜스 Unity 프로젝트입니다.  
플레이어는 스테이지를 선택한 뒤 드래그 앤 드롭으로 타워를 설치하고, 웨이브 단위로 몰려오는 적을 막아 골인지점을 방어합니다.

현재 프로젝트는 ScriptableObject 기반 밸런스 데이터, 경로 ID 기반 웨이브 스폰, 씬 단위 오브젝트 풀, 싱글톤 매니저와 옵저버형 UI 갱신 구조를 중심으로 구성되어 있습니다.

## 기술 스택

- Unity 2022.3.61f1
- TextMesh Pro 3.0.7
- UGUI
- ScriptableObject 기반 데이터 구성
- Physics Raycast + Drag and Drop 타워 배치
- Scene-based Object Pool
- Singleton / Observer 패턴 기반 런타임 매니저

## 핵심 기술 소개

### 1. ScriptableObject 기반 밸런스 데이터

- `WaveSequenceSO.cs` : 웨이브 시퀀스를 스테이지 단위로 정의하고, `WaveStage`와 `WaveEntry`를 통해 적 종류, 수량, 간격, 시작 지연을 데이터로 관리합니다.
- `EnemyStatsSO.cs` : 적의 체력, 이동 속도, 공격력, 보상 골드, 보스 여부를 ScriptableObject로 분리해 밸런싱과 재사용을 쉽게 만듭니다.
- `TowerBaseStatsSO.cs` : 타워 가격, 공격력, 사거리, 공격 속도, 치명타, 범위 공격, 버프/디버프 수치를 데이터화해 각 타워 프리팹이 같은 구조를 공유하도록 구성합니다.

### 2. 웨이브 진행과 경로 기반 적 스폰

- `WaveController.cs` : 웨이브 시작 지연, 단계별 스폰, 진행도 계산, 다음 웨이브 스킵, 러시 보너스 지급까지 포함한 전체 웨이브 루프를 관리합니다.
- `EnemySpawner.cs` : 적 스탯 SO와 경로 ID를 받아 실제 적 프리팹을 소환하고, HP 바와 함께 풀에서 꺼내 전장에 배치합니다.
- `MapManager.cs` : 여러 `WaypointPath`를 경로 ID 기준 딕셔너리로 캐싱해 스포너가 필요한 이동 경로를 빠르게 찾을 수 있게 합니다.
- `GoalTrigger.cs` : 적이 골에 도달했을 때 일반 적은 라이프 감소, 보스는 즉시 게임 오버 처리로 연결합니다.

### 3. 타워 배치와 업그레이드 구조

- `Draggable.cs` / `DropZone.cs` : UI에서 선택한 타워 아이콘을 드래그해 배치 타일에 놓는 입력 흐름을 담당합니다.
- `TowerSpot.cs` : 타워 설치 가능 위치와 현재 점유 상태를 관리하는 배치 지점 컴포넌트입니다.
- `UpgradeManager.cs` : 설치, 업그레이드, 판매를 하나의 진입점에서 처리하고, 골드 차감과 타워 교체를 함께 관리합니다.
- `TowerStorage.cs` : 타워 타입과 레벨별 프리팹을 딕셔너리로 정리해 배치와 업그레이드 시 필요한 프리팹을 빠르게 조회합니다.

### 4. 전투 런타임 구조

- `TowerBase.cs` : 타워 공통 공격 루프, 타겟 탐지, 발사, 버프 적용 흐름을 제공하는 베이스 클래스입니다.
- `BallistaTower.cs`, `CannonTower.cs`, `CatapultTower.cs`, `TurretTower.cs`, `BuffTower.cs`, `DebuffTower.cs` : 관통, 범위 공격, 치명타, 공격 속도 버프, 슬로우 등 역할별 전투 행동을 파생 클래스로 분리했습니다.
- `EnemyBase.cs` : 적의 이동, 공격, 피해 처리, 사망 애니메이션, 풀 반납까지 적 단위의 런타임 상태를 담당합니다.
- `BulletManager.cs` / `BulletBase.cs` : 총알 타입별 생성과 재사용을 관리하며, 개별 탄환은 목표 추적과 데미지 적용을 수행합니다.

### 5. 게임 상태, UI, 씬 전환 프레임워크

- `GameManager.cs` : 라이프, 골드, 웨이브, 남은 적 수를 통합 관리하고 승리/패배 화면 출력까지 담당합니다.
- `Notify.cs` 와 `IGameGoldObserver`, `IGameLifeObserver`, `IGameWaveObserver` : UI가 게임 상태 변경을 구독하는 간단한 옵저버 구조를 제공합니다.
- `GameGoldUI.cs`, `GameLifeUI.cs`, `GameWaveUI.cs` : GameManager 이벤트를 받아 HUD를 즉시 갱신합니다.
- `SceneChanger.cs` : 타이틀, 스테이지 선택, 각 스테이지 씬 전환을 단순한 인터페이스로 통합합니다.
- `SoundManager.cs` / `EffectManager.cs` : 효과음, 배경음, 전투 이펙트를 이름 기반으로 재생하는 공용 매니저입니다.

### 6. 런타임 최적화

- `PoolService.cs` : 씬 단위로 프리팹별 오브젝트 풀을 관리해 적, 총알, HP 바 같은 반복 생성 오브젝트를 재사용합니다.
- `ObjectPool.cs` : 제네릭 큐 기반 풀 구현체로 예열, 반환, 재활성화 흐름을 공통화합니다.
- `IPoolable.cs` : 풀에서 꺼낼 때와 반납할 때 필요한 초기화 로직을 각 객체가 직접 정의할 수 있게 합니다.

## 기술 결정 기록

장르 특성상 전투 흐름, 웨이브 구성, 배치 UX, 반복 생성 오브젝트 처리 방식이 프로젝트 구조에 큰 영향을 주기 때문에 해당 항목을 중심으로 기술 결정 기록을 정리했습니다.

### ADR-001. ScriptableObject 기반 밸런스 데이터

배경 : 타워 종류와 적 종류가 늘어나면서 체력, 공격력, 가격, 사거리, 스폰 수량 같은 수치를 코드에 직접 고정하면 수정 비용이 커질 수 있었습니다.

결정 : 웨이브, 적, 타워 수치를 `WaveSequenceSO`, `EnemyStatsSO`, `TowerBaseStatsSO` 기반 ScriptableObject로 분리했습니다.

채택 이유 : ScriptableObject는 Unity 에디터 안에서 수치를 직접 다루기 쉽고, 프리팹과 런타임 로직을 분리해 밸런싱 반복 속도를 높이기 좋습니다. 또한 같은 구조를 여러 스테이지와 여러 타워에 재사용할 수 있어 확장에 유리하다고 판단했습니다.

### ADR-002. 경로 ID 기반 웨이브 스폰 구조

배경 : 한 스테이지 안에서도 적 종류와 스폰 타이밍, 진입 경로를 다르게 구성할 수 있어야 했고, 맵 로직과 웨이브 로직이 서로 강하게 묶이지 않도록 할 필요가 있었습니다.

결정 : 웨이브 엔트리에는 적 정보와 함께 `pathId` 를 넣고, `MapManager` 가 이를 실제 `WaypointPath` 로 해석하는 구조를 채택했습니다.

채택 이유 : 웨이브 데이터와 맵 경로를 느슨하게 연결하면 같은 스테이지에서도 다양한 조합을 만들기 쉽고, 특정 경로만 교체하거나 추가하는 작업도 단순해집니다. 스포너 입장에서는 ID만 알면 되므로 맵 변경이 전투 로직에 미치는 영향도 줄일 수 있습니다.

### ADR-003. 드래그 앤 드롭 기반 타워 배치

배경 : 타워 종류를 빠르게 선택하고 월드에 배치하는 흐름이 필요했으며, UI 선택과 실제 설치 로직을 분리해 유지보수성을 확보하고 싶었습니다.

결정 : `Draggable` UI 아이콘, 월드 `DropZone`, 배치 지점 `TowerSpot`, 설치와 업그레이드 진입점 `UpgradeManager` 로 역할을 나누는 구조를 채택했습니다.

채택 이유 : 입력 UI와 설치 검증을 분리하면 타워 선택 방식이 바뀌어도 핵심 배치 로직을 그대로 유지할 수 있습니다. 또한 설치 가능 여부, 골드 차감, 타워 점유 상태를 한 곳에서 제어하기 쉬워집니다.

### ADR-004. 씬 단위 오브젝트 풀링

배경 : 적, 총알, HP 바, 이펙트처럼 전투 중 반복 생성되는 오브젝트가 많아질수록 Instantiate/Destroy 비용이 커질 가능성이 높았습니다.

결정 : `PoolService` 와 `ObjectPool<T>` 를 사용해 씬 전용 풀을 두고, 적과 총알, HP 바를 재사용하는 구조를 채택했습니다.

채택 이유 : 씬 단위 풀은 전역 자원 관리보다 단순하고, 전투 씬을 나가면 함께 정리되므로 라이프사이클을 이해하기 쉽습니다. 전투 중 생성과 삭제를 줄이면 프레임 드랍 가능성을 낮추고, 반복 사용 오브젝트의 초기화 흐름도 표준화할 수 있습니다.

### ADR-005. GameManager 중심 상태 관리와 옵저버형 UI 갱신

배경 : 라이프, 골드, 웨이브 진행도 같은 정보는 여러 UI가 동시에 참조해야 하므로, 각 UI가 직접 값을 조회하는 구조는 결합도가 높아질 수 있었습니다.

결정 : `GameManager` 가 전투 상태를 통합 관리하고, `Notify<T>` 기반 옵저버 구조로 UI에 변경 사항을 전달하는 방식을 채택했습니다.

채택 이유 : HUD가 GameManager의 공개 이벤트만 구독하도록 만들면 UI와 전투 로직의 책임이 분리됩니다. 상태 변경 경로가 한 곳으로 모이기 때문에 디버깅이 쉬워지고, 새로운 UI를 추가할 때도 같은 이벤트 흐름을 재사용할 수 있습니다.

### ADR-006. 싱글톤 기반 공용 매니저와 씬 전환 구조

배경 : 사운드, 이펙트, 게임 상태, 씬 전환처럼 여러 화면에서 공통으로 쓰는 기능은 접근 경로가 단순해야 했습니다.

결정 : `SingleTon<T>` 베이스 클래스를 두고 `GameManager`, `SceneChanger`, `SoundManager`, `EffectManager`, `TowerStorage`, `UpgradeManager` 등의 공용 매니저를 싱글톤으로 관리했습니다.

채택 이유 : 학습 비용이 낮고 Unity 프로젝트에서 빠르게 공용 기능을 붙이기 좋습니다. 또한 타이틀, 스테이지 선택, 전투 씬을 오가는 구조에서 공용 매니저 접근 방식을 통일할 수 있어 구현 속도와 일관성을 확보하기 쉬웠습니다.

## 핵심 흐름

### 스테이지 진입

- `SceneChanger.cs` 가 타이틀과 스테이지 선택 화면에서 각 전투 씬으로 이동시킵니다.
- 전투 씬이 시작되면 `GameManager.cs` 가 라이프, 골드, 웨이브 상태를 초기화하고 HUD를 갱신합니다.

### 웨이브 진행

- `WaveController.cs` 가 현재 스테이지에 연결된 `WaveSequenceSO` 를 읽어 웨이브를 순차 실행합니다.
- 각 `WaveEntry` 는 적 종류, 수량, 간격, 경로 ID를 담고 있고, `EnemySpawner.cs` 가 이를 실제 적 오브젝트로 전개합니다.
- `MapManager.cs` 와 `WaypointPath.cs` 는 경로 ID를 실제 이동 경로로 변환합니다.

### 전투와 방어

- 플레이어는 UI 타워 아이콘을 드래그해 `DropZone` 이 있는 타일에 배치합니다.
- `UpgradeManager.cs` 와 `TowerStorage.cs` 가 골드를 확인한 뒤 타워를 설치하거나 상위 단계 프리팹으로 교체합니다.
- 각 타워는 `TowerBase.cs` 계층에서 적을 탐지하고 발사하며, 적은 `GoalTrigger.cs` 에 닿기 전까지 경로를 따라 이동합니다.

### 상태 갱신과 종료 처리

- 적 처치와 타워 설치는 `GameManager.cs` 의 골드, 웨이브, 라이프 상태를 갱신합니다.
- `GameGoldUI.cs`, `GameLifeUI.cs`, `GameWaveUI.cs` 는 옵저버 이벤트를 받아 UI를 반영합니다.
- 모든 웨이브 종료 후 적이 남아 있지 않으면 승리, 라이프가 0이 되거나 보스가 골에 도달하면 패배 처리됩니다.

## 실행 방법

1. Unity 2022.3.61f1로 프로젝트를 엽니다.
2. `Assets/Scene/Title.unity` 를 시작 씬으로 열고 Play 합니다.
3. 타이틀에서 스테이지를 선택한 뒤 전투 씬에서 타워를 배치하고 업그레이드하며 플레이합니다.

빌드 설정에 등록된 씬은 아래 순서입니다.

- `Title`
- `StageSelect`
- `Stage1`
- `Stage2`
- `Stage3`
